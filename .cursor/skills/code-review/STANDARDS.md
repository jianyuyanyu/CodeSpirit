# CodeSpirit 代码审查标准

本文档详细说明 CodeSpirit 项目的代码审查标准，基于项目的 24 个规则文件。

## 审查原则

1. **优先级驱动**：先检查严重问题，再检查重要问题，最后检查建议改进
2. **规范一致性**：确保代码符合项目规范，保持团队代码风格一致
3. **质量保证**：通过审查提升代码质量，减少潜在问题
4. **教育性**：提供修复建议和代码示例，帮助开发者改进

## 审查维度

### 1. 安全性审查

**检查项**：
- 密码存储方式（必须哈希）
- SQL 注入风险（禁止字符串拼接）
- 敏感信息泄露（日志、DTO）
- 特殊权限需求（检查是否需要 `[Permission]` 特性配置权限继承）

**注意**：框架会自动生成权限（格式：`{module}_{controller}_{action}`），大部分情况下无需手动配置权限特性。

**严重性**：🔴 严重

### 2. 数据库审查

**检查项**：
- 雪花 ID 配置（`ValueGeneratedNever()`）
- DbContext 使用（迁移必须使用数据库特定 DbContext）
- 多租户隔离（实体实现 `IMultiTenant`）
- 审计字段（实体继承 `AuditableEntityBase`）

**严重性**：🔴 严重

### 3. 异步编程审查

**检查项**：
- 阻塞调用（禁止 `Task.Result`、`Task.Wait()`）
- 同步 I/O（必须使用 `async/await`）
- 异步循环（使用批量处理）

**严重性**：🔴 严重

### 4. 多语言审查

**检查项**：
- 硬编码字符串（必须使用资源文件）
- Display 特性（DTO 属性添加多语言支持）
- 资源文件（中英文资源文件）
- 验证消息本地化

**严重性**：🟡 重要

### 5. DTO 规范审查

**检查项**：
- 验证特性（`[Required]`、`[StringLength]`）
- 查询 DTO 继承（继承 `QueryDtoBase`）
- AutoMapper 配置（完善映射配置）

**严重性**：🟡 重要

### 6. 控制器规范审查

**检查项**：
- DisplayName 特性（所有方法添加）
- Navigation 特性（控制器添加菜单配置）
- 操作特性（`[Operation]`、`[HeaderOperation]`）
- 返回类型（`ActionResult<ApiResponse<T>>`）
- 匿名访问标记（`[AllowAnonymous]` 用于公开 API）

**权限系统说明**：
- ✅ 框架自动生成权限，格式：`{module}_{controller}_{action}`
- ✅ 大部分情况无需手动配置权限特性
- ⚠️ 仅在需要权限继承或自定义权限时使用 `[Permission]` 特性

**严重性**：🟡 重要

### 7. 服务类规范审查

**检查项**：
- 基类继承（`BaseCRUDService`）
- XML 文档注释（公共成员）
- 依赖注入标记（`IScopedDependency`）

**严重性**：🟡 重要

### 8. EF Core 查询审查

**检查项**：
- AsNoTracking（只读查询）
- N+1 查询（使用 `Include()`）
- AsSplitQuery（多对多关联）
- 批量操作（`ExecuteUpdateAsync`、`ExecuteDeleteAsync`）

**严重性**：🟡 重要

### 9. 代码注释审查

**检查项**：
- XML 文档注释（公共成员）
- 行内注释（复杂业务逻辑）
- 枚举注释（枚举值）

**严重性**：🟢 建议

### 10. 命名规范审查

**检查项**：
- 实体命名（单数形式）
- DTO 命名（`Create{Entity}Dto`、`Update{Entity}Dto`）
- 控制器命名（复数形式）
- 服务命名（`{Entity}Service`）

**严重性**：🟢 建议

## 审查流程

1. **准备阶段**：确定审查范围，准备审查工具
2. **执行阶段**：按优先级逐项检查
3. **报告阶段**：生成审查报告，提供修复建议
4. **跟进阶段**：跟踪问题修复情况

## 审查工具

- **IDE 代码分析**：使用 Visual Studio / Rider 的代码分析功能
- **静态分析工具**：SonarQube、CodeQL 等
- **搜索功能**：搜索常见违规模式
- **规则文件**：参考项目的 24 个规则文件

## 审查报告格式

审查报告应包含：
- 问题分类（严重、重要、建议）
- 问题描述（具体问题）
- 文件位置（文件路径和行号）
- 修复建议（如何修复）
- 代码示例（正确示例）

详见 [report-template.md](report-template.md)。
