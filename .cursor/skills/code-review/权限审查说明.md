# CodeSpirit 权限审查说明

## 核心原则

**CodeSpirit 采用自动权限生成机制，大部分情况下无需手动配置权限特性。**

## 权限生成机制

### 自动生成规则

框架会根据控制器和方法自动生成权限代码：

**格式**：`{module}_{controller}_{action}`

**示例**：
- `identity_users_create` - 身份模块-用户控制器-创建方法
- `exam_questions_getList` - 考试模块-题目控制器-获取列表方法
- `identity_roles_delete` - 身份模块-角色控制器-删除方法

### 生成规则

1. **module**：从项目配置或 `[Module]` 特性获取
2. **controller**：控制器名称（去掉 Controller 后缀）
3. **action**：方法名称（HttpGet/HttpPost 等映射到对应操作）

## 何时无需配置权限特性

✅ **以下情况无需添加权限特性**：

1. **标准 CRUD 操作**
   ```csharp
   [HttpGet]
   [DisplayName("获取用户列表")]
   public async Task<ActionResult<ApiResponse<PageList<UserDto>>>> GetUsers(
       [FromQuery] UserQueryDto queryDto)
   {
       // 自动生成权限：identity_users_getUsers
   }
   
   [HttpPost]
   [DisplayName("创建用户")]
   public async Task<ActionResult<ApiResponse<UserDto>>> CreateUser(CreateUserDto dto)
   {
       // 自动生成权限：identity_users_createUser
   }
   ```

2. **自定义业务操作**
   ```csharp
   [HttpPut("{id}/unlock")]
   [Operation("解锁", "ajax", null, "确定要解除用户锁定吗？")]
   [DisplayName("解锁用户")]
   public async Task<ActionResult<ApiResponse>> UnlockUser(long id)
   {
       // 自动生成权限：identity_users_unlockUser
   }
   ```

3. **批量操作**
   ```csharp
   [HttpPost("batch/delete")]
   [Operation("批量删除", "ajax", null, "确定要批量删除?", null, true)]
   [DisplayName("批量删除用户")]
   public async Task<ActionResult<ApiResponse>> BatchDelete([FromBody] BatchOperationDto<long> request)
   {
       // 自动生成权限：identity_users_batchDelete
   }
   ```

## 何时需要配置权限特性

⚠️ **以下情况需要使用 `[Permission]` 特性**：

### 1. 需要权限继承

允许拥有父权限的用户访问子操作：

```csharp
[HttpPut("{id}")]
[Permission(
    Name = "exam_questions_update",
    AllowInheritedPermissions = new[] { "exam_questions_manage", "exam_questions_admin" })]
[DisplayName("更新题目")]
public async Task<ActionResult<ApiResponse<QuestionDto>>> Update(long id, UpdateQuestionDto dto)
{
    // 拥有 exam_questions_manage 或 exam_questions_admin 权限的用户也可以访问
}
```

### 2. 需要自定义权限名称

覆盖默认生成的权限代码：

```csharp
[HttpPost("special-operation")]
[Permission(Name = "identity_users_special")]  // 自定义权限名称
[DisplayName("特殊操作")]
public async Task<ActionResult<ApiResponse>> SpecialOperation()
{
    // 使用自定义权限：identity_users_special
}
```

### 3. 需要添加权限描述

为权限添加详细说明：

```csharp
[HttpDelete("{id}")]
[Permission(
    Name = "identity_users_delete",
    DisplayName = "删除用户",
    Description = "允许永久删除用户账号，此操作不可恢复",
    Parent = "identity_users")]
[DisplayName("删除用户")]
public async Task<ActionResult<ApiResponse>> DeleteUser(long id)
{
    // 带详细描述的权限配置
}
```

## 特殊控制器标记

### 公开 API 控制器

需要匿名访问的控制器（如登录、注册）：

```csharp
[AllowAnonymous]
[Navigation(Hidden = true)]  // 隐藏导航菜单
[NoAudit("授权控制器不需要审计")]
public class AuthController : ApiControllerBase
{
    // 所有方法都允许匿名访问
}
```

### 内部 API 控制器

微服务间内部通信的控制器：

```csharp
[DisableAggregator]  // 禁用 API 聚合
[DisplayName("内部用户信息")]
[Module("default")]
[Route("api/identity/internal/users")]
[NoAudit("内部 API 不需要审计")]
public class InternalUsersController : ControllerBase  // 继承 ControllerBase
{
    // 内部 API 方法
}
```

## 代码审查检查清单

### ❌ 不要标记为问题

- [ ] 控制器方法缺少 `[RequirePermission]` 特性
- [ ] 标准 CRUD 操作未配置权限特性
- [ ] 自定义业务操作未配置权限特性

### ✅ 应标记为问题

- [ ] 需要权限继承但未使用 `[Permission]` 特性配置 `AllowInheritedPermissions`
- [ ] 公开 API（登录、注册、重置密码等）未标记 `[AllowAnonymous]`
- [ ] 内部 API 未标记 `[DisableAggregator]`
- [ ] 匿名控制器未配置 `[Navigation(Hidden = true)]`

## 审查示例

### ✅ 正确示例 1：标准 CRUD

```csharp
[DisplayName("用户管理")]
[Navigation(Icon = "fa-solid fa-users", PlatformType = PlatformType.Tenant)]
public class UsersController : ApiControllerBase
{
    // ✅ 无需权限特性，自动生成：identity_users_getUsers
    [HttpGet]
    [DisplayName("获取用户列表")]
    public async Task<ActionResult<ApiResponse<PageList<UserDto>>>> GetUsers([FromQuery] UserQueryDto queryDto)
    {
        var users = await _userService.GetUsersAsync(queryDto);
        return SuccessResponse(users);
    }
    
    // ✅ 无需权限特性，自动生成：identity_users_create
    [HttpPost]
    [DisplayName("创建用户")]
    public async Task<ActionResult<ApiResponse<UserDto>>> Create(CreateUserDto dto)
    {
        var user = await _userService.CreateAsync(dto);
        return SuccessResponse(user);
    }
}
```

### ✅ 正确示例 2：权限继承

```csharp
[DisplayName("题目管理")]
[Navigation(Icon = "fa-solid fa-question", PlatformType = PlatformType.Tenant)]
public class QuestionsController : ApiControllerBase
{
    // ✅ 配置权限继承
    [HttpPut("{id}")]
    [Permission(AllowInheritedPermissions = new[] { "exam_questions_manage" })]
    [DisplayName("更新题目")]
    public async Task<ActionResult<ApiResponse<QuestionDto>>> Update(long id, UpdateQuestionDto dto)
    {
        // 拥有 exam_questions_manage 权限的用户也可以访问
        var result = await _questionService.UpdateAsync(id, dto);
        return SuccessResponse(result);
    }
}
```

### ✅ 正确示例 3：公开 API

```csharp
// ✅ 正确标记匿名访问
[AllowAnonymous]
[Navigation(Hidden = true)]
[NoAudit("授权控制器不需要审计")]
public class AuthController : ApiControllerBase
{
    [HttpPost("login")]
    [DisplayName("用户登录")]
    public async Task<ActionResult<ApiResponse<AuthTokenResponse>>> Login([FromBody] LoginModel model)
    {
        // 公开 API，允许匿名访问
    }
}
```

### ❌ 错误示例：不必要的权限特性

```csharp
// ❌ 不需要：框架会自动生成权限
[HttpPost]
[RequirePermission("identity_users_create")]  // ❌ 不需要
[DisplayName("创建用户")]
public async Task<ActionResult<ApiResponse<UserDto>>> Create(CreateUserDto dto)
{
    // ...
}

// ✅ 正确：只需 DisplayName 特性
[HttpPost]
[DisplayName("创建用户")]
public async Task<ActionResult<ApiResponse<UserDto>>> Create(CreateUserDto dto)
{
    // 框架自动生成权限：identity_users_create
}
```

## 服务层权限检查

如果需要在服务层检查权限，使用 `IHasPermissionService`：

```csharp
public class QuestionService : IScopedDependency
{
    private readonly IHasPermissionService _permissionService;

    public QuestionService(IHasPermissionService permissionService)
    {
        _permissionService = permissionService;
    }

    public async Task<bool> CanManageQuestionAsync()
    {
        // 检查用户是否拥有指定权限
        return _permissionService.HasPermission("exam_questions_manage");
    }
    
    public async Task<bool> CanAccessModuleAsync()
    {
        // 检查导航权限（仅检查一二级权限）
        return _permissionService.HasNavigationPermission("exam_questions");
    }
}
```

## 总结

1. **默认情况**：框架自动生成权限，无需手动配置
2. **特殊情况**：需要权限继承时使用 `[Permission]` 特性
3. **公开 API**：使用 `[AllowAnonymous]` 标记
4. **审查重点**：检查特殊场景的标记是否正确，而非检查是否缺少权限特性
